Threat Vector Remediation Details

Direct architectural fixes aligned with OWASP Top 10 standards

All Vectors Mitigated
2.1 Prevention of Mass Automated Account Creation Active Defense
Threat Profile
Botnets executing automated curl/Python scripts against /api/auth/signup to generate thousands of bogus restaurant store accounts, inflating cloud storage, exhausting database connections, and reserving unauthorized storefront URLs.
Implemented Remediation
  • Sliding-Window IP Throttle: Enforced ceiling of 3 account creations per hour per IP. Subsequent attempts receive HTTP 429 Too Many Requests with standard RFC Retry-After headers.
  • Invisible Bot Honeypot: Embedded hidden website_hp parameter. Automated scrapers filling all form fields are detected and instantly rejected.
  • Slug Normalization: Unicode sanitization and strict 30-character length clamping on store slugs.
2.2 Brute-Force & Credential Stuffing Defense Dual-Tier Lockout
Threat Profile
Malicious actors launching dictionary attacks or credential stuffing against restaurant manager and administrator login accounts on /api/auth/login.
Implemented Remediation
  • Dual-Tier Lockout Matrix: Throttles failed attempts to 5 per 15 minutes per IP AND 5 per 15 minutes per target email account. Distributed botnets attacking a single manager account are locked out regardless of IP rotation.
  • Timing-Safe Responses: Missing accounts and bad passwords return identical generic "Invalid email or password" messages, denying attackers username enumeration capability.
2.3 Order Flooding & Kitchen Terminal DoS Defense Kitchen Protection
Threat Profile
Competitors or griefers triggering automated scripts to submit 500 fake orders in seconds via /api/orders, ringing restaurant kitchen tablets non-stop and filling kitchen display queues with fraudulent tickets.
Implemented Remediation
  • Order Throttle: Enforced ceiling of 5 orders per 10 minutes per IP/client. Ample headroom for genuine dining customers, zero tolerance for automated order floods.
  • Order Honeypot: Integrated silent order_hp verification into order intake schema.
2.4 File Upload & Remote Code Execution (RCE) Hardening Strict Whitelisting
Threat Profile
Uploading executable server-side scripts (.php, .exe, .sh, .phtml) disguised as dish images to gain Remote Code Execution (RCE), or uploading 500MB video files to deplete server bandwidth and disk space.
Implemented Remediation
  • Strict Size Ceiling: Capped at 5 MB maximum per upload.
  • Whitelist Only: Rejects everything except validated image types: image/jpeg, image/png, image/webp, image/svg+xml, image/gif.
  • Filename Cryptographic Re-Keying: User-supplied filenames are stripped of path traversal sequences (../) and re-keyed with high-entropy alphanumeric timestamps.
2.5 Global Security HTTP Headers (Edge Middleware) Global Edge Shield
Threat Profile
Man-in-the-middle attacks, iframe clickjacking, cross-site scripting (XSS), and MIME-type confusion attacks.
Implemented Remediation (middleware.js)
  • Strict-Transport-Security: max-age=31536000; includeSubDomains; preload
  • X-Frame-Options: DENY (Blocks clickjacking via iframes)
  • X-Content-Type-Options: nosniff (Blocks MIME confusion)
  • Referrer-Policy: strict-origin-when-cross-origin
  • Permissions-Policy: camera=(), microphone=(), geolocation=(self)
